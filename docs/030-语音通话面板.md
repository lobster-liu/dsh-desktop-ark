# 语音通话面板（半双工）

> 会话页右上角那颗玻璃球：点一下 → 对着手机/耳机说话 → 自动识别、发送、等回复、朗读回复。
> 本文记录这一版（`call-panel74` / commit `d1a2426`）的交互、内部链路、配置项、构建方式、已知边界与排障清单。

## 1. 它长什么样

| 位置 | 内容 |
|---|---|
| 会话页右上角 | 玻璃球入口（圆形半透明 + 线条电话 SVG + 局部高光）。**只挂在会话页**：首页、设置、插件页都不显示；空白新会话也显示（判据见 §7） |
| 通话面板 | 标题行 `语音通话` + 「设置」文字按钮；状态行；「我说」原文；「DSH」回复；云端失败原因（红字常驻）；输入源徽标（`蓝牙麦 · 12.4 秒 · 峰值 15033`）；三个按钮 `说话 / 停止朗读 / 挂断` |
| 按钮语义 | `说话`：开录（说 `打断并说话` 时表示先掐掉正在念的回复）；`停止朗读`：只停朗读、不退出通话；`挂断`：任何时候都可按，退出通话 |

面板状态机：`idle → listening → thinking → speaking → idle`，任一步失败停在 `error` 并把原因写在状态行/红字里。挂断或打断会让本轮在下一个 `await` 处自行退出（`callTurnId` 版本号）。

## 2. 一次通话的时序

```
点「说话」
  ├─ 立刻开录（不先等页面：以前先探会话，用户开口的头几个字被丢掉）
  │    └─ VAD：有人声就继续，静音 0.9–2.2 秒（三档可配）+ 句尾补 0.4 秒 收尾
  ├─ 识别：云端 qwen3-asr-flash 优先；失败/未配置 → 系统离线引擎（分段）
  ├─ 发送：页面内同步 XHR `POST /api/session/prompt`（mode=queue）
  ├─ 等回复：1 秒轮询页面 DOM，认「轮次页脚」为结束标志（最长 240 秒）
  └─ 朗读：云端 TTS 优先（合成 → 音频 → 页面 `new Audio()`），失败回退系统 TTS
```

## 3. 录音（`HostCapabilities.ets`）

- **VAD**：每块算 RMS；`noiseFloor = noiseFloor*0.7 + chunkRms*0.3`（初值 80），`threshold = max(300, noiseFloor*3)`。
- **收尾条件**：`voicedMs >= minVoicedMs(400) && silenceRunMs >= silenceMs` → `stopReason='silence'`；一直没声音 `2500ms` → `'empty'`；到 `maxMs` → `'max'`；字节上限 `16000*2*120` → `'bytes'`。达成静音后再补 `tailMs = 400` 的句尾（期间有人声就清零），避免「换气处被截」。
- **停顿三档**（设置页）：`快 0.7 秒 / 普通 1.3 秒 / 耐心 2.2 秒` → `pauseSilenceMs()`。
- **麦克风三档**：`蓝牙耳机优先 / 自动（手机麦优先）/ 只用手机麦`。默认 `auto`。
- **蓝牙 SCO 要「叫醒」**：`CALL_INPUT_DEVICES` 平时不列耳机（`type=7`）。先做一次 0.5 秒 `SOURCE_TYPE_VOICE_COMMUNICATION` 采集（结果丢弃），再重新枚举就能拿到；`orderBluetooths()` 会把上次成功收音的设备 id 排最前。日志：`蓝牙叫醒 peak=…` → `蓝牙尝试 id=… peak=…`。
- 开头延迟：蓝牙已在列表里时直接开录（`蓝牙已在列表里，直接录（准备 ~120ms）`）。

## 4. 识别

**云端（默认，需在设置页填 key）**：`qwen3-asr-flash`，走 OpenAI 兼容 chat completions：

```
POST {asrBase}/chat/completions
{ "model":"qwen3-asr-flash",
  "messages":[{"role":"user","content":[{"type":"input_audio",
              "input_audio":{"data":"data:audio/wav;base64,…"}}]}],
  "stream":false, "asr_options":{"language":"zh"} }
```

其它兼容 `/audio/transcriptions` 的服务（如 SiliconFlow）也支持：模型名不以 `qwen` 开头即走 multipart。

**离线回退（系统 `@kit.CoreSpeechKit`）**：

- `createEngine({ language:'zh-CN', online:1, extraParams:{ locate:'CN', recognizerMode:'long' } })`
- `startListening` 的 `extraParams`：`{ recognitionMode:1, maxAudioDuration:60000, recognizerOption:{ enablePartialResult:true } }`（`maxAudioDuration` 是关键：缺了它引擎约 3 秒就自己收尾，后面的音频全丢）
- `writeAudio` **640 字节 / 20 ms**；一段喂满 2 秒且当前块 RMS < 400（句间停顿）就换会话，否则 6 秒硬切；各段文本拼起来
- 引擎自己结束时（`onComplete`）不要继续写，也不要把 `1002200010` 当致命错误——先取已识别文本

## 5. 发送（不碰输入框）

```
POST /api/session/prompt
{ "type":"client-request", "rpcId":"<uuid>", "method":"session/prompt",
  "payload":{"args":{"request":{
    "requestId":"<uuid>", "sessionId":"<来自 localStorage['dsh.sessions.current']>",
    "mode":"queue", "content":[{"type":"text","text":"…"}],
    "clientTimeZone":"Asia/Shanghai" }}}}
```

为什么不用页面输入框：输入框是 Lexical 编辑器，清不掉草稿、写入会把软键盘和输入法语音助手顶出来；而空会话直发也能正确落进新会话。用**同步 XHR** 是为了让 `runJavaScript` 直接拿到状态码（异步 fetch 在这个桥上只能拿回"started"）。

## 6. 读回复与朗读

**读**（`buildReadScript()`，页面内执行）：

1. 先找**轮次页脚**——文本含 `本轮费用` / `未定价用量`，或含 `[class*="timeEnd"]`。没有页脚 = 这一轮还没定型，继续等；
2. 从页脚往前找第一条正文；跳过：用户侧条目（`[class*="userRow"]`）、**思考块**（首行 `思考`/`推理`、类名含 `hink|eason|hought`、或 `details>summary` 标着思考）、来源标签（`time-context` 等）、过程状态行（`运行中/思考/提问/等待回答/网页搜索/已完成/…`）、上下文注入行（`Time sampled while preparing …`）；
3. `waitForReply` 要求「回复变了 + 条目数变多 + 连续两次读到一致」，**240 秒**窗口；超时也把已经看到的最后一段正文交出去朗读。

**念**：

- 云端：`qwen3-tts-flash`（`POST {ttsBase}/services/aigc/multimodal-generation/generation`）或 `cosyvoice-v3-flash`（`POST {ttsBase}/services/audio/tts/SpeechSynthesizer`）。两家都只返回 `output.audio.url|data`，所以**由 Host 侧下载落盘**，页面用 `/_ohos/speech/tts-audio?id=…` 取；
- 长文本**分段并发**：CosyVoice 120 字/段、Qwen 300 字/段、3 路并发、每段 90 秒超时，`concatWav()` 拼 PCM；面板等待窗口 120 秒；
- 播放需要 `.mediaPlayGestureAccess(false)`：否则 ArkWeb 以「用户没和页面交互过」拒绝 `play()`；
- 只有表情/符号的回复直接跳过（路由也回 `422 speech/no-speakable-text`）；
- 回退：任何一步失败都降级到系统 TTS，并把原因写进面板红字。

## 7. 入口显示判据（右上角玻璃球）

`buildChromeProbeScript()` 每 1.2 秒算一次，返回 `'1'` 才显示：

1. `localStorage['dsh.sessions.current']` 有 `sessionId`（没有就是首页）；
2. 是会话视图：有 `[class*="flowItem"]`、或有含 `发送消息` 的按钮、或 composer 靠下半屏、或同时出现 `对话`/`轨迹` 两个页签；
3. 入口点 `(innerWidth-44, 96)` 向上找祖先，命中「全屏（≥85%×85% 或 ≥80% 宽）且 class/role 含 `overlay|dialog|sheet|modal|drawer`」就判定被设置页/插件页遮住 → `'0'`（正则里**不能**含 `panel`，否则连会话主面板一起误伤）。

## 8. 设置文件

`<应用沙箱>/runtime/voice-settings.json`（`context.filesDir/runtime`，与 Node 侧的 runtime 目录是同一个），ArkTS 与 Node 各读一份：

```json
{
  "recognizer": "auto|deepseek|cloud|system",
  "voice": "system|cloud",
  "pause": "quick|normal|patient",
  "mic": "auto|bluetooth|phone",
  "cloud": {
    "key": "sk-…",
    "asrBase": "https://ws-xxxx.cn-beijing.maas.aliyuncs.com/compatible-mode/v1",
    "asrModel": "qwen3-asr-flash",
    "ttsBase": "https://ws-xxxx.cn-beijing.maas.aliyuncs.com/api/v1",
    "ttsModel": "qwen3-tts-flash",
    "ttsVoice": "Cherry"
  }
}
```

- 阿里云百炼的 `sk-ws-` key 是**业务空间专属**，只能配业务空间域名（`https://<WorkspaceId>.cn-beijing.maas.aliyuncs.com/...`）；配成公共 `dashscope.aliyuncs.com` 会一律 `403 Model.AccessDenied`。
- `cosyvoice-v3.5-flash` 只接受**克隆/设计音色**（ID 形如 `cosyvoice-v3.5-flash-xxxx`），系统音色请用 `cosyvoice-v3-flash` / `v3-plus`；保存设置时若模型与音色跨产品线会自动纠正并提示。
- 识别 Base 与朗读 Base 不同域时，朗读 Base 会跟随识别域名派生（`/api/v1`）。

## 9. 随包的 Node 路由（`packages/speech-to-text-ohos`）

| 路由 | 作用 |
|---|---|
| `POST /_ohos/speech/record` | 录一段（透传 `durationMs/maxMs/silenceMs/minVoicedMs/autoStop/mic`） |
| `POST /_ohos/speech/recognize` | 离线识别指定 pcm 文件 |
| `POST /_ohos/speech/cloud-asr` | 云端识别（`{path}` 或 `{audioBase64}`） |
| `POST /_ohos/speech/cloud-tts` | 云端合成，落盘后返回 `{id,url,bytes,chunks}` |
| `GET /_ohos/speech/tts-audio?id=…` | 取合成音频 |
| `GET|POST /_ohos/speech/settings` | 读 / 写语音设置 |
| `POST /_ohos/speech/speak`、`/_ohos/speech/speak-stop`、`/_ohos/speech/mic-test` | 系统 TTS、停止、麦克风自检 |

这一层是 seam 插件，构建前必须重打载荷：`node scripts/package-payload.mjs --force`。

## 10. 构建与装机

```bash
export DEVECO_SDK_HOME='<DevEco>/sdk'
export PATH='<DevEco>/jbr/bin:<DevEco>/tools/node:<DevEco>/tools/hvigor/bin':$PATH
node scripts/package-payload.mjs --force
hvigorw --mode module -p product=default -p buildMode=debug assembleHap --no-daemon
java -jar hap-sign-tool.jar sign-app -mode localSign -keyAlias <alias> \
  -appCertFile <cert> -profileFile <p7b> -signAlg SHA256withECDSA \
  -keystoreFile <p12> -compatibleVersion 12 -signCode 1 \
  -keystorePwd <pwd> -keyPwd <pwd>
hdc install -r entry-default-signed.hap && hdc shell aa start -a EntryAbility -b <bundle>
```

注意两点：`AppScope/app.json5` 的 `bundleName` 必须与签名 p7b 一致（否则 `9568329 verify signature failed`），提交前务必还原；`aa start` 在锁屏时报 `10106102`，需先解锁（开发者模式不能自动解锁）。

## 11. 已知边界

- **半双工**：不能边说边听；全双工需要流式识别管道（`writeAudio` 持续喂 + 打断判定），尚未实现。
- **耳机麦要叫醒**：首轮可能多花 0.5–1 秒；若耳机只有 A2DP 无 HFP 麦，叫醒后能量仍≈0（`rms≈20`）。
- **系统 TTS 会截断长文本**（415 字只念约 11 秒，且 `onComplete` 提前谎报）⇒ 长回复必须走云端朗读。
- **云端朗读有固定等待**：约 8 字/秒 × 3 路并发，几百字需要十几到二十几秒才开始出声。
- **识别准确率**：离线模型对远场/含糊语音较差；云端明显更好但需要联网与有效 key。

## 12. 排障清单（`payload/app.log` 关键字）

| 日志 | 含义 |
|---|---|
| `speech.record 输入候选 …` | 本次枚举到的输入设备（`type=15` 手机麦，`type=7` SCO 耳机麦） |
| `speech.record 蓝牙叫醒 peak=…` | 叫醒采集的能量；≈0 表示耳机没把麦给 App |
| `speech.capture 收尾 reason=silence total=… voiced=…` | VAD 判定；`voiced` 远小于 `total` 说明停顿阈值太敏感 |
| `speech.record done: … input=phone|bluetooth` | 这一轮用的是哪路麦克 |
| `speech.recognize sent …B（sessions=n）→ out: n chars` | 离线识别分段数；`sessions=1` 且字数很少 ⇒ 音频本身有问题 |
| `云端识别失败 HTTP 403：Model.AccessDenied` | key 与域名不匹配，或该模型未开通 |
| `speech.speak 本机不支持增强路由` | 增强路由不可用，朗读走系统默认出口（通常仍是耳机 A2DP） |
| `speech.speak done: N chars → estimate Mms` | 系统 TTS 的估算时长；`onComplete` 提前属已知问题 |
| `云端合成失败 HTTP 400：InvalidParameter` | 文本里没有可合成内容（纯表情/符号） |
| `speech.capture 收尾 reason=empty` | 完全没听到人声（麦克风错、耳机麦静音、或权限） |

## 13. 实时字幕（流式识别，全双工的地基）

设置页「实时字幕 = 开（边说边显字）」时，通话走另一条采集链路：麦克风一直读，边读边把
640 字节/20 毫秒的 PCM 喂给系统识别引擎，面板上随 partial 结果实时出字；判定「说完」
之后拿累计文本走同一条发送 / 读回复 / 朗读链路。

- 与半双工的区别只在采集：半双工是「录完 → 整段识别」，识别要等说话结束；实时字幕反过来，
  说话过程中就有文本，后续要接全双工（朗读期间继续听、用户一开口就打断朗读）也靠这条管道。
- 宿主能力：`speech.captionStart`（开麦 + 建引擎）/ `speech.captionSnapshot`（快照：文本、
  `voicedMs`、`silenceMs`、`peak`、`sessions`、`error`）/ `speech.captionStop`（停麦、取回文本）。
  ArkTS 侧另有 `startCaptionForCall` / `captionSnapshotForCall` / `stopCaptionForCall` 薄包装。
- 引擎节奏（沿用 DSH Go 的 `HmsStreamingAsr`）：`writeAudio` 单次 640 字节、每 20 毫秒一次；
  一段会话约 3 秒会被引擎自己收尾，收尾后立刻换新会话接着喂；`onResult.isFinal` 是句子边界，
  `interim` 单独存，句子定型后清空（否则界面上同一句话会出现两次）。
- 收尾口径：`voicedMs ≥ 400` 且 `silenceMs ≥ 停顿档位（0.7 / 1.3 / 2.2 秒）` → 说完；
  8 秒内一句人声都没有 → 直接报「没听清」；最长 30 秒。
- 现在仍不是全双工：字幕只在「听」的阶段显示，回复朗读时麦克风是关的（避免把喇叭声录进去）。
